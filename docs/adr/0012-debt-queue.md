# ADR 0012 — 기술부채를 지표로 재고, 자동 백로그에 쌓고, 큐로 나눠 갚는다

- 상태: 채택 (27강)
- 맥락: 0010(리뷰어 견고화)·0011(적대적 다중화·집계)로 **잡는 것**은 결정적으로 만들었다.
  그런데 집계가 게이트 비대상으로 분류한 🟡 Nit·🟣 Pre-existing 은 갈 곳이 없었다.
  "나중에" 하고 머지하면 어디에도 안 적히고 PR 이 닫히는 순간 묻힌다. 잡기만 하고
  흘려보낼 데가 없으면 루프가 아니라 구멍이다(0009 피드백 루프).

## 결정 1 — 부채는 감이 아니라 지표로 잰다

`scripts/scan_debt.py` 가 TODO/FIXME · 커버리지 · mutation score 를 **모듈별로** 뜬다.
전체 합 하나로는 어디를 고칠지 모른다. 같은 코드에 같은 스캔을 돌리면 같은 숫자가 나오므로
측정도 결정적이다. 판정 문구도 규칙으로 고정한다(커버 50% 미만 → 커버부터 / mutation 90% 미만 → 테스트 보강).

- 무거운 스캔(mutation)은 기본으로 돌리지 않는다 — `--mutation` 을 줄 때만.
  부채를 재는 일이 또 다른 부채가 되면 안 된다.

## 결정 2 — 리뷰 산출은 사람 손이 아니라 훅이 백로그로 흘려보낸다

`Stop`·`SubagentStop` 훅(`.claude/hooks/append-backlog.sh`)이 입력 JSON 의
`last_assistant_message` 를 읽어 🟡🟣 를 뽑아 `BACKLOG.md` 에 append 한다.

- 25강 output-style 로 포맷을 고정해 둔 것이 여기서 **파싱 가능성**으로 돌아온다.
  자유 문장이면 자동 append 가 불가능하다 — 그 제약이 자산이었다.
- append 는 **file:line 을 키로 병합**한다. 같은 리뷰를 열 번 돌려도 한 줄로 수렴한다.
  중복이 쌓이면 갚을 양을 셀 수 없고, 세지 못하면 상환 계획을 못 세운다.
- 같은 이벤트의 훅은 전부 병렬로 돈다. 21강 `gate-pytest.sh` 를 덮어쓰지 않고 `Stop` 배열에 나란히 둔다.

## 결정 3 — 큐를 분리한다. 섞으면 양방향으로 무너진다

    논파(FP)                      →  폐기
    confirm + 🔴 Important        →  긴급 큐 · 머지 차단 게이트(0009·14강)
    그 외 🟡 Nit·🟣 Pre-existing  →  부채 큐 · BACKLOG.md · 스프린트 상환

- 급한 것을 부채 큐에 넣으면 유출이 "나중에"로 분류돼 프로덕션에 나간다 — 게이트가 무의미해진다.
- 부채로 머지를 막으면 팀이 게이트를 우회하기 시작하고, 그 우회로로 진짜 긴급도 샌다(0009 게이트 형식화).
- 분류는 심각도 태그가 결정적으로 한다. 사람이 매번 "급한가 아닌가"를 고민하지 않는다.

## 결정 4 — 부채 큐 안에서 "누가 갚나"는 3조건이 가른다

    저위험 ∧ 가역 ∧ 테스트 격리  전부 충족  →  자동 큐(에이전트가 상환)
    하나라도 미충족                         →  사람 큐

세 조건 다 기계가 답한다: 저위험 = 규칙표 키워드 ∧ 핵심 모듈(guardrails·llm·pension_calc·mcp_client)
아님 / 가역 = 구조 변경 키워드 없음 / 테스트 격리 = `tests/test_<모듈>.py` 존재.
조건 없이 "자동으로 갚는다"를 맡기면 부채 상환이 새 사고의 생산이 된다.

- 25강 `checklist.md` 수정 라우팅의 3조건과 같은 기준이고, **30강 파이널에서 부채 상환
  에이전트를 채점하는 기준**으로 다시 쓴다.
- 부채 큐 안의 우선순위 가중(가드레일이 로깅보다 무겁다)은 **사람의 도메인 판단**이다.
  결정성은 여기까지고, 그 앞은 정직하게 사람 몫으로 둔다.
