# ADR 0004 — 테스트 품질은 커버리지가 아니라 mutation score로 본다

## 상태
채택

## 맥락
`app/guardrails.py`는 라인 커버리지가 100%인데도 출력 유출 판정을 검증하는
assert가 하나도 없었다. "실행됐나"와 "검증됐나"가 다르다는 것이 mutmut으로
드러났다 — 보강 전 killed 44 / 64 (68.8%).

## 결정
- 가드레일·금액 계산처럼 틀리면 사고가 나는 **핵심 모듈만** mutation으로 측정한다.
- 임계는 **80%**. 미달이면 머지 차단(CI에서 score 파싱 → exit 1).
- 매 편집이 아니라 CI 주기 실행. mutation은 느리다.

## 이유
equivalent mutant 때문에 100%는 원래 불가능하다. 남은 생존 mutant를 억지로
죽이려 들면 문자열을 그대로 베끼는 과적합 테스트가 된다 — 그건 품질이 아니다.

## 결과
- 보강 후 `app.guardrails` killed 53 / 64 (82.8%) — 임계 통과.
- 남은 11개는 전부 판정에 영향이 없는 것들이다:
  - `mask_emails` 6개 — `split("@")` 최대분할 수 변형 등, 단일 `@`·`.` 입력에서
    결과가 동일한 **equivalent mutant**.
  - 나머지 5개 — 차단 사유 문자열의 내용 변형(대소문자·접두사). 사유가 채워졌는지는
    검사하지만 문장을 통째로 베끼지는 않는다(과적합 방지).
- `Edit(tests/**)` deny(14강)는 해제했다 — 테스트를 늘리는 것이 이 강의 작업이다.
  게이트 게이밍 방어는 리뷰와 mutation score가 대신한다.
