# ADR 0005 — 외부 호출은 실패를 가정하고 상한·폴백·흔적으로 견딘다

## 상태
채택

## 맥락
`app/llm.py`는 LLM 호출을 `try/except`로 감싸 `[LLM 오류 fallback]`을 돌려주는
폴백 한 줄만 있었다. 타임아웃이 없어 느린 응답에 무한정 매달리고, 재시도가 없어
일시 장애에 곧바로 폴백으로 빠지고, 로그가 없어 하루에 몇 번 실패하는지 아무도
몰랐다 — "폴백만 있고 관측이 없는" 반쪽 신뢰성.

## 결정
- **타임아웃은 명시한다.** `LLM_TIMEOUT_S`(기본 30초). 기본값에 기대지 않는다.
  MCP는 `MCP_TIMEOUT`(연결/시작)·`MCP_TOOL_TIMEOUT`(호출 응답)을 `settings.json` env에 고정한다.
- **재시도는 분류해서 상한 안에서.** 429·500·502·503·504·타임아웃·연결 오류만 재시도,
  401·403·404 등 상태 불변 오류는 즉시 폴백. 지수 백오프 + 지터, 429는 `Retry-After` 존중.
  상한 `LLM_MAX_RETRIES`(기본 3) = 곧 비용 캡.
- **조회는 멱등** — 재시도 안전. 쓰기를 붙이면 멱등키를 실어야 한다.
- **폴백은 fail-closed.** 조용히 틀린 값 대신 명시적 실패 문자열.
- **모든 갈림길에 로그.** 성공·재시도·소진·비재시도 실패를 `pension_qa.llm` 로거에 남긴다.
- **상한은 모델이 아니라 시스템이 강제한다.** `settings.json` env + PreToolUse `mcp__.*` 훅
  (`.claude/hooks/guard-external.sh`, 정책 없으면 exit 2).

## 결과
- `tests/test_llm.py` 8건이 정책을 고정한다(타임아웃 명시·분류·상한·Retry-After·폴백·로그).
- 재시도 상한을 올리는 것은 비용 상한을 올리는 것이다 — 변경 시 이 ADR을 갱신한다.
