# ADR 0002 — 근거 부실은 2단 임계로 보류·저신뢰 구분

## 상태
채택 (2026-07)

## 맥락
`agent.ask()`는 검색 결과가 **완전히 빌 때만** 차단했다. `retriever.search()`는
토큰 겹침이 `score > 0`이기만 하면 문서를 돌려주고 점수는 버리므로, 질문 토큰 4개 중
1개만 겹친 문서로도 LLM이 호출되고 그 답변이 정상 답변(`✅`)과 같은 모양으로 나갔다.
가드레일 규칙의 fail-closed 원칙("판정이 애매하면 차단으로 기운다")과 어긋나는 구간.

전면 차단은 반대 방향으로 과했다. 실측상 `"연금 해지하면 어떻게 되나요"`(커버리지 0.25)처럼
근거가 약하지만 무의미하지는 않은 질문이 있고, 이를 잡담과 같이 취급하면 답변 가능 범위가 과하게 줄어든다.

## 결정
검색 점수에 **2단 임계**를 둔다. 판정 기준은 절대 겹침 개수가 아니라
**질문 토큰 대비 커버리지 비율** — 질문이 길수록 겹침 개수가 자연히 커지기 때문.

```
0.00 ─── 보류 ─── 0.15 ── 저신뢰 ── 0.40 ─── 정상 ─── 1.00
```

- **보류**: `blocked=True`, LLM **미호출**, 단 `sources`(문서 이름)는 채워 노출
- **저신뢰**: 평소대로 답변 + `Result.low_confidence=True` → CLI `⚠️`
- **정상**: 현행 유지

임계값은 현재 `data/` 3개 문서 실측 분포로 잡았다(잡담 0.07 / 해지 질문 0.25 / 정상 질문 0.50~0.75).
저신뢰는 답변 문자열이 아니라 `Result` 필드로 표시하고, 점수 수치는 노출하지 않는다.
커버리지 **계산**은 `retriever.py`, 임계 **판정**은 `guardrails.py`에 둔다.

## 결과
- 근거 없는 답변이 정상 답변으로 위장되지 않고, 하드 미달 시 LLM 비용·외부 전송도 절약.
- 보류해도 관련 문서 이름은 보여줘 사용자가 다음 행동을 잡을 수 있다.
- 트레이드오프: 비율 기준이라 **짧은 질문에서 게이트가 무력**하다 —
  `"연금"` 한 단어는 커버리지 1.00으로 통과한다. 최소 토큰 수 가드는 미도입, 필요해지면 추후 ADR.
- 트레이드오프: 조사가 붙은 토큰(`한도가` vs `한도`)이 안 겹쳐 커버리지가 실제보다 낮게 나온다.
  임계값이 이 저평가를 흡수하고 있어, **검색기를 임베딩으로 바꾸면 임계값은 재캘리브레이션 대상**이다.
- 트레이드오프: 임계값을 상수로 하드코딩했다(환경변수 설정화는 범위 밖). 문서가 늘면 재측정 필요.
